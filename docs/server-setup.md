# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины
- **Гипервизор:** Oracle VM VirtualBox 7.2.20
- **Гостевая операционная система:** Linux / Ubuntu Server 24.04 LTS (x86_64)
- **Объём оперативной памяти:** 2048 МБ (2 ГБ)
- **Количество процессорных ядер:** 2 vCPU, ограничение загрузки 100%
- **Объём дискового накопителя:** 25 ГБ, динамически расширяемый VDI (`devops-vm.vdi`)
- **Имя узла (Hostname):** `devops-vm`
- **Полное доменное имя (FQDN):** `devops-vm.devops.local`

## 2. Сетевые интерфейсы
1. **Сетевой адаптер 1 (NAT):**
   - Назначение: Обеспечение доступа гостевой ОС во внешнюю сеть Интернет (установка обновлений и пакетов через `apt`), проброс управляющего порта SSH с хостовой системы.
   - IP-адрес интерфейса `enp0s3`: `10.0.2.15/24` (шлюз `10.0.2.2`).
2. **Сетевой адаптер 2 (Host-only / Виртуальный адаптер хоста):**
   - Назначение: Изолированный сегмент между хостовой системой и виртуальной машиной для прямого обращения по IP и локальному доменному имени (доступ к веб-серверу в ПР №6).
   - Адаптер на хосте: `VirtualBox Host-Only Ethernet Adapter` (`192.168.56.1/24`).
   - IP-адрес интерфейса `enp0s8`: `192.168.56.101/24` (выдан встроенным DHCP-сервером VirtualBox).

## 3. Правило проброса портов
- **Адаптер подключения:** Адаптер 1 (NAT)
- **Имя правила:** `ssh`
- **Протокол:** TCP
- **Адрес хостовой системы:** `127.0.0.1`
- **Порт хостовой системы:** `2222`
- **Адрес гостевой системы:** *(не заполняется / 0.0.0.0)*
- **Порт гостевой системы:** `2222` *(изменён с начального 22 в процессе Hardening)*

## 4. Учётные записи
1. `student` / `le` (UID 1000):
   - Первичная учётная запись администратора системы, созданная при начальной установке ОС Ubuntu Server.
   - Член групп: `le`, `adm`, `cdrom`, `sudo`, `dip`, `plugdev`, `lxd`.
2. `devops` (UID 1001):
   - Выделенная сервисно-административная учётная запись для удалённого управления узлом и запуска плейбуков автоматизации (Ansible в ПР №11).
   - Член групп: `devops`, `sudo`, `users`.
   - Способ аутентификации: исключительно по асимметричному криптографическому ключу SSH (алгоритм Ed25519, открытый ключ в `~/.ssh/authorized_keys`). Парольная аутентификация принудительно отключена.

## 5. Служба SSH
- **Фактический порт прослушивания:** `2222` (нестандартный порт для противодействия автоматическому сканированию сети).
- **Файл конфигурации усиления защиты:** `/etc/ssh/sshd_config.d/99-hardening.conf`
- **Ключевые директивы конфигурации:**
  - `Port 2222` — номер рабочего сетевого порта службы;
  - `PermitRootLogin no` — категорический запрет аутентификации суперпользователя `root`;
  - `PasswordAuthentication no` — полное отключение парольной проверки подлинности;
  - `PubkeyAuthentication yes` — разрешение входа по открытым ключам;
  - `PermitEmptyPasswords no` — запрет учетных записей с пустыми паролями;
  - `MaxAuthTries 3` — ограничение попыток подбора ключей в рамках одной сессии до 3;
  - `LoginGraceTime 30` — таймаут ожидания завершения аутентификации 30 секунд;
  - `AllowUsers devops` — ограничение списка учётных записей, имеющих право входа;
  - `X11Forwarding no` — отключение проброса графической подсистемы X11;
  - `ClientAliveInterval 300` и `ClientAliveCountMax 2` — контроль активности клиента и завершение зависших сессий.
- **Особенности дистрибутива Ubuntu 24.04:**
  - Деактивирован системный сокет: `sudo systemctl disable --now ssh.socket`;
  - Активирован постоянный системный сервис: `sudo systemctl enable --now ssh.service`;
  - В файле `/etc/ssh/sshd_config.d/50-cloud-init.conf` закомментирована директива `PasswordAuthentication yes`.

## 6. Правила межсетевого экрана (UFW)
- **Политики по умолчанию (Default policies):**
  - Входящий трафик: `deny` (`sudo ufw default deny incoming`) — принцип наименьших привилегий;
  - Исходящий трафик: `allow` (`sudo ufw default allow outgoing`).
- **Перечень разрешающих правил:**
  - `2222/tcp (SSH rate-limited)`: действие `LIMIT` (блокирует IP-источник, инициировавший 6 и более попыток соединения в течение 30 секунд);
  - `80/tcp (HTTP)`: действие `ALLOW` (подготовлено для работы веб-сервера Nginx в ПР №6);
  - `443/tcp (HTTPS)`: действие `ALLOW` (подготовлено для защищённого TLS-трафика веб-сервера в ПР №6).
- **Уровень аудита и регистрации событий:**
  - `sudo ufw logging medium`;
  - Журнал заблокированных пакетов ведется в `/var/log/ufw.log`.

## 7. Снимки состояния (Snapshots)
1. `01-clean-install` — исходный снимок чистой ОС сразу после завершения инсталляции и выполнения `sudo apt update && sudo apt upgrade -y`.
2. `02-keys-configured` — снимок после создания пользователя `devops`, генерации ключа `devops_vm` на хосте, переноса публичного ключа и настройки конфигурации клиента `~/.ssh/config`.
3. `03-ssh-hardened` — снимок после применения конфигурации безопасности SSH (порт 2222, отключение root и паролей, включение UFW c правилом LIMIT, обновление правил проброса NAT в VirtualBox).
4. `04-nginx-https` — снимок после установки Nginx, перевода ресурса devops.local на HTTPS с самоподписанным сертификатом, настройки редиректа 301 с HTTP на HTTPS и отключения дефолтного хоста.

## 8. Веб-сервер
- **Устанавливаемый пакет:** `nginx` (установка: `sudo apt update && sudo apt install -y nginx`).
- **Путь к конфигурации ресурса:** `/etc/nginx/sites-available/devops-site` (активирован через символическую ссылку в `/etc/nginx/sites-enabled/devops-site`; стандартный ресурс `/etc/nginx/sites-enabled/default` отключён).
- **Каталог публикуемого ресурса:** `/var/www/devops-site/` (директива `root`).
  - Владелец каталога и файлов: `devops:devops`.
  - Права доступа: `755` (`drwxr-xr-x`) для каталогов, `644` (`-rw-r--r--`) для файлов (модель «владелец пишет, веб-сервер www-data читает»).
- **Криптографический сертификат и закрытый ключ TLS:**
  - Путь к открытому сертификату: `/etc/ssl/certs/devops.crt` (владелец `root:root`, права `644` — чтение доступно всем).
  - Путь к закрытому ключу: `/etc/ssl/private/devops.key` (владелец `root:root`, права `600` — доступ строго суперпользователю, запрещён для `www-data`).
  - Команда формирования сертификата:
    ```bash
    sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
      -keyout /etc/ssl/private/devops.key \
      -out /etc/ssl/certs/devops.crt \
      -subj "/CN=devops.local" \
      -addext "subjectAltName=DNS:devops.local"
    ```
  - Срок действия сертификата: 365 дней. Поле SAN: `DNS:devops.local`.
  - Поддерживаемые протоколы: `TLSv1.2 TLSv1.3`.
- **Сетевые параметры и перенаправление:**
  - Порт 80: HTTP (перенаправление 301 Permanent Redirect на `https://$host$request_uri`).
  - Порт 443: HTTPS (обслуживание защищённого TLS-трафика).


## 9. Контейнеризация
- **Способ установки Docker Engine и версия:** официальный репозиторий Docker (`https://download.docker.com/linux/ubuntu`), версия Docker Engine 29.9.2, Docker Compose v5.6.1.
- **Участники группы docker:** `devops` (позволяет выполнять команды `docker` и `docker compose` без вызова `sudo`).
- **Расположение проекта на сервере:** `/home/devops/app` (файлы `Dockerfile`, `docker-compose.yml`, `requirements.txt`, `app.py`, `.env`).
- **Расположение файла .env и его права:** `/home/devops/app/.env`, владелец `devops:devops`, права `600` (`-rw-------`). Исключён из контекста сборки через `.dockerignore` и из репозитория Git через `.gitignore`.
- **Публикуемые порты и адреса:**
  - Сервис `app`: проброс порта `127.0.0.1:5000:5000` (доступен исключительно на локальной петле, недоступен из внешней сети).
  - Сервис `db` (PostgreSQL): порт `5432` не опубликован на хост-систему, доступен только внутри изолированной сети Compose `backend`.
- **Именованные тома:** `db_data` (каталог `/var/lib/docker/volumes/app_db_data/_data`, монтируется в `/var/lib/postgresql/data` в контейнере СУБД) для обеспечения постоянства данных при пересоздании контейнеров (`docker compose down` сохраняет том; удаление тома возможно только с флагом `-v`).
- **Конфигурация обратного прокси-сервера (Nginx):**
  - Блок `location /app/` в файле `/etc/nginx/sites-available/devops-site`.
  - Директива `proxy_pass http://127.0.0.1:5000/;` (со слешем на конце для отсечения префикса `/app/`).
  - Проброс заголовков: `Host $host`, `X-Real-IP $remote_addr`, `X-Forwarded-For $proxy_add_x_forwarded_for`, `X-Forwarded-Proto $scheme`.
